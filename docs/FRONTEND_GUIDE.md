# Web UI Guide
This guide explains how to use the AIMagnetics web interface and what each input/output means.

---
## The Interface
When you open `http://localhost:8080`, you'll see a two-column layout:
**Left Column:** Design Requirements input form  
**Right Column:** Design Summary (results)

---
## Input Fields
### 1. Inductance (µH)
**What it is:** The desired inductance value for your buck inductor.
**Example:** `250` (µH)
**How to find it:**
- Typically specified in your buck converter circuit design
- Often labeled as "L_out" or "Load inductor" in schematics
- Typical range: 1–10,000 µH
**Why it matters:**
- Too small: Inductor can't store enough energy (current ripple too high)
- Too large: Oversized, heavier, more expensive
- Energy stored: E = 0.5 × L × I²

---
### 2. Peak Current (A)
**What it is:** The maximum current that flows through the inductor during operation.
**Example:** `2.0` (Amps)
**How to find it:**
- Look at your output load: I_max ≈ (V_out / R_load) + ripple margin
- Or simulate your buck circuit and measure peak inductor current
- Typical range: 0.1–100 A
**Why it matters:**
- Drives core size (higher current → larger Ap requirement)
- Determines wire heating (I²R losses)
- Affects saturation risk (Bmax limit)

---

### 3. Switching Frequency (kHz)
**What it is:** How fast your buck converter switches (PWM frequency).
**Example:** `100` (kHz)
**How to find it:**
- Look at your PWM controller datasheet or schematic
- Common values: 50 kHz, 100 kHz, 250 kHz, 500 kHz
- Typical range: 1–10,000 kHz
**Why it matters:**
- Different materials are optimal at different frequencies (low freq → Powder Iron, high freq → Ferrite)
- Higher frequency → more core losses (hysteresis + eddy current)
- Affects the size/cost tradeoff

---

### 4. Temperature Rise (°C)
**What it is:** How much hotter than ambient your inductor core can get without damage.
**Example:** `40` (°C)
**How to find it:**
- Material datasheet: typical limit is 40–100°C above ambient
- Thermal design constraint: must stay below Curie temperature
- Typical range: 20–100°C
**Why it matters:**
- Core loss and wire loss generate heat
- Too tight (e.g., 20°C): requires larger, more expensive core
- Too loose (e.g., 100°C): risk of material degradation or solder reflow issues

---

## Generate Recommendation
Click the **"Generate Recommendation"** button to run the design algorithm.
**Behind the scenes:**
1. Material Selection: Chooses best material for frequency
2. Area Product: Calculates minimum core size
3. Core Selection: Finds available core from database
4. Loss Calculation: Predicts copper loss, core loss, temperature rise
**Processing time:** < 1 second (typically)

---
## Design Summary (Results)
Once you click "Generate Recommendation," the right column shows the results:
### Material
- **What it shows:** The selected magnetic material (e.g., "Kool Mu")
- **Example:** "Kool Mu"
- **What it means:** This material is best for 100 kHz operation (lowest loss, good saturation margin)
### Core Part Number
- **What it shows:** The exact part number from the database
- **Example:** "0077440A7"
- **What it means:** You can order this part number from the supplier
### Core Geometry
Shows key dimensions:
- **Ac (cm²):** Cross-sectional area of magnetic core
- **Wa (cm²):** Window area available for copper winding
- **Le (cm):** Magnetic path length (affects inductance index AL)
### Inductance Index (AL)
- **Unit:** nH per 100 turns (nH/100T)
- **Example:** "125"
- **Formula:** AL = L / (N/100)² (after winding N turns)
### Calculated Turns
- **What it shows:** How many wire wraps you need to achieve your desired inductance
- **Example:** "18"
- **What it means:** Wind 18 complete loops of copper wire around the core
- **Practical check:**
  - < 5 turns: Very thick wire needed; impractical
  - > 100 turns: Very thin wire; prone to copper loss; may not fit in window
### Losses
- **Copper Loss (W):** Heat generated by resistive wire losses (I²R)
- **Core Loss (W):** Heat from magnetic cycling (hysteresis + eddy current)
- **Total Loss (W):** Sum of copper + core
- **What it means:** Your design dissipates this much power as heat; ensure cooling is adequate
### Predicted Temperature Rise
- **What it shows:** Calculated temperature above ambient, based on losses and thermal resistance
- **Example:** "35°C"
- **Status:**
  - ✅ Green (≤ allowed): Design is safe
  - ⚠️ Yellow (> allowed by 5°C): Marginal; may need thermal improvement
  - ❌ Red (> allowed): Design overheats; choose larger core or different material

---
## Workflow: Iterative Design
Most designs require **iteration**:
1. **First pass:** Enter initial guess for temperature rise (e.g., 40°C)
2. **Check result:** Does predicted rise match your allowable? If not, adjust one input:
   - Too hot? → Increase temperature rise allowance OR lower current requirement OR switch to lower frequency
   - Still too cold? → Reduce allowable rise (tighter constraint) to optimize for cost/size
3. **Refine:** Adjust any input and regenerate
4. **Verify:** Once satisfied, check that calculated turns is reasonable (5–100 range)

---
## Troubleshooting Results
### "No cores meet the Ap requirement"
- **Why:** Database doesn't have a core large enough
- **Solution:**
  - Reduce inductance (smaller L → smaller core needed)
  - Increase allowed temperature rise (larger core allowed)
  - Reduce peak current (smaller core needed)
  - Check if you need to add larger cores to `data/cores.csv`
### Turns count is 2 (too low)
- **Why:** Very large core selected
- **Solution:**
  - This is okay if core geometry permits large wire
  - Check if a smaller core is available in database
### Turns count is 200 (too high)
- **Why:** Very small core or tight constraints
- **Solution:**
  - Increase inductance requirement OR increase core size manually
  - May need to add smaller inductance value to database
### Temperature rise is very high (e.g., 80°C when limit is 40°C)
- **Why:** Losses are high (tight design)
- **Solution:**
  - Switch to lower frequency (if circuit allows)
  - Reduce peak current (if possible)
  - Allow higher temperature rise (relax constraint)
  - Use a different material (lower loss at this frequency)

---
## Interpreting "Alternatives"
Sometimes the tool shows alternatives (e.g., "Ferrite 3C90, Powder Iron"). These are other materials that work at the selected frequency but may have different cost/loss tradeoffs.
**Ferrite at 100 kHz:**
- Pro: Lower loss than Kool Mu
- Con: More expensive, tighter temperature control
- Use if: Cost is not a constraint and you want minimum losses
**Powder Iron at 100 kHz:**
- Pro: More forgiving temperature range, good saturation
- Con: Higher loss (larger core needed)
- Use if: You prioritize reliability over efficiency

## Typical Design Scenarios
### Low-Power USB Charger (< 5W, 5V out, < 1A)
- L = 10 µH, Ipk = 1.5 A, f = 500 kHz, ΔT = 40°C
- Expected: Small ferrite core, Turns ≈ 5, Loss < 0.1W
### Mid-Power Board (20W, 12V out, 2A)
- L = 250 µH, Ipk = 3 A, f = 100 kHz, ΔT = 40°C
- Expected: Medium Kool Mu core, Turns ≈ 25, Loss ≈ 0.5W
### High-Power Supply (100W, 48V out, 5A)
- L = 500 µH, Ipk = 7 A, f = 50 kHz, ΔT = 50°C
- Expected: Large Kool Mu or Powder Iron core, Turns ≈ 40, Loss ≈ 2W
